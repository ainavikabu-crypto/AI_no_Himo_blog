## 1. ブログライターAIエージェント

**ノード名**: `ブログライターAIエージェント`

このノードは、Perplexityの調査結果を基に、完全なブログ記事を生成します。

### デフォルトプロンプトの構造

```
あなたは、日本のビジネスやテクノロジー分野の高品質なブログ記事を作成する
マーケティングチームの一員です。

[役割定義]
[コンテンツ要件]
[追加要件]
[出力フォーマット]
```

### カスタマイズ例

#### 例1: カジュアルなブログに変更

```javascript
あなたは、日本のビジネスやテクノロジー分野の親しみやすいブログ記事を作成する
コンテンツライターです。読者に寄り添い、会話するようなトーンで書いてください。

// トーンを変更
- フレンドリーで会話的なトーンを使用する
- 「です・ます」調ではなく、「だ・である」調も適宜使用
- 読者に直接語りかけるような表現を使う（例：「あなたも〜してみませんか？」）
```

#### 例2: 専門家向けブログに変更

```javascript
あなたは、IT業界の専門家向けに技術的に深い記事を作成する
テクニカルライターです。

// 専門性を高める
- 業界用語や専門用語を積極的に使用する
- 技術的な詳細や実装例を含める
- ソースコードやコマンド例を含める場合がある
- 3000〜5000文字の長さにする
```

#### 例3: ニュース記事風に変更

```javascript
あなたは、最新のビジネスニュースを報道するジャーナリストです。

// ニュース記事のスタイル
- 客観的で中立的なトーンを使用する
- 5W1H（誰が、何を、いつ、どこで、なぜ、どのように）を明確にする
- 最も重要な情報を冒頭に配置する（逆ピラミッド型）
- 1200〜1800文字の長さにする
```

#### 例4: リスト記事に変更

```javascript
あなたは、実用的なリスト記事を作成するコンテンツライターです。

// リスト記事のスタイル
- 「〇〇の方法10選」のような番号付きリスト形式で書く
- 各項目に見出しと詳細説明を含める
- 各項目は100〜200文字程度にする
- 実践的なアドバイスやヒントを含める
```

### カスタマイズポイント

| 項目 | デフォルト | カスタマイズ例 |
|------|-----------|---------------|
| 文字数 | 2000〜3000文字 | 1000〜1500文字（短め）<br>3000〜5000文字（長め） |
| トーン | プロフェッショナル | カジュアル、フォーマル、フレンドリー |
| 対象読者 | ビジネスパーソン | 初心者、専門家、経営者、学生 |
| 記事タイプ | 解説記事 | ニュース、リスト記事、ハウツー、レビュー |

## 2. タイトル・スラッグ・メタ作成

**ノード名**: `タイトル・スラッグ・メタ作成`

このノードは、SEO最適化されたタイトル、URLスラッグ、メタディスクリプションを生成します。

### デフォルトプロンプトの構造

```
以下のブログ投稿のために、スラッグ、タイトル、メタディスクリプションを作成してください

[スラッグのガイドライン]
[タイトルのガイドライン]
[メタディスクリプションのガイドライン]
[出力フォーマット]
```

### カスタマイズ例

#### 例1: キャッチーなタイトル重視

```javascript
タイトルのガイドライン：
- 「驚きの〜」「知らないと損する〜」など、興味を引くフレーズを使用
- 数字を含める（例：「5つの方法」「3ステップで」）
- 問いかけ形式も効果的（例：「〜できていますか？」）
- 簡潔で魅力的、理想的には20-30文字程度
- クリックしたくなるような表現を使う
```

#### 例2: SEO重視

```javascript
タイトルのガイドライン：
- 主要キーワードをタイトルの最初の方に配置
- 年号を含める（例：「2025年版」）
- 「完全ガイド」「徹底解説」などの権威性を示す言葉を使用
- 理想的には28-32文字以内
- Google検索結果で切れないように調整

メタディスクリプションのガイドライン：
- 主要キーワードと関連キーワードを自然に含める
- ターゲットユーザーが検索しそうな言葉を使用
- 65-75文字以内に収める
- 検索意図に明確に応える内容にする
```

#### 例3: ブランディング重視

```javascript
タイトルのガイドライン：
- ブランド名や会社名をタイトルに含める
- 独自の視点や専門性を強調する
- ポジティブで前向きな表現を使用
- 「〜で解決」「〜で成功」など、ベネフィットを明示

メタディスクリプションのガイドライン：
- 会社の専門性や独自の強みを簡潔に伝える
- 「〇〇の専門家が解説」「実績〇〇件の〜」など、権威性を示す
- 読者が得られる具体的な価値を明示
```

## 3. HTML作成

**ノード名**: `HTML作成`

このノードは、ブログ記事をWordPress互換のHTML形式に変換します。

### デフォルトプロンプトの構造

```
前置きや説明なしに、HTMLコンテンツのみを出力してください。

[コンテンツ処理]
[必須構造]
[スタイル要件]
[エンゲージメントフォーマット]
[ハイパーリンク処理]
[WordPress互換性]
```

### カスタマイズ例

#### 例1: シンプルなHTML構造

```javascript
### 必須構造（この順序で）：
1. タイトル（H2）
2. メインコンテンツ（適切な見出し階層）
3. まとめセクション

// 推定読了時間、目次、FAQは省略
```

#### 例2: リッチコンテンツ

```javascript
### 必須構造（この順序で）：
1. タイトル（H2）
2. アイキャッチ画像
3. 推定読了時間と公開日
4. 著者情報
5. 重要ポイント（3-5箇条書き）
6. 目次（すべての見出しにリンク）
7. メインコンテンツ
8. 関連記事リンク
9. よくある質問セクション
10. CTAボタン
```

#### 例3: ブランドカラーに変更

```javascript
### スタイル要件：
- スタイルオーバーライド：!important宣言を含むスタイルセクションを含める
- リンク：すべてのハイパーリンクは#ff6b6b（赤系）にする
- 見出し：すべての見出しに#4ecdc4（青緑系）の下線とパディングを追加
- ボタン：CTAボタンは#ffe66d（黄色）の背景にする
```

## 4. Perplexity調査

**ノード名**: `Perplexity調査実行`

このノードは、Perplexity APIを使用してトピックを調査します。

### デフォルトプロンプトの構造

```json
{
  "model": "sonar-pro",
  "messages": [
    {
      "role": "system",
      "content": "あなたは信頼性の高い情報源から詳細な情報を見つけることができるプロのリサーチャーです。日本語で回答してください。"
    },
    {
      "role": "user",
      "content": "以下のトピックについて調査し、見つけたすべての情報を返してください：'{{ $json['調査キーワード'] }}'。信頼できる情報源からの最新情報を含めてください。"
    }
  ]
}
```

### カスタマイズ例

#### 例1: より具体的な調査指示

```json
{
  "role": "user",
  "content": "以下のトピックについて調査してください：'{{ $json['調査キーワード'] }}'。\n\n特に以下の点に焦点を当ててください：\n1. 最新のトレンドと統計データ\n2. 専門家の意見や分析\n3. 具体的な事例やケーススタディ\n4. 今後の予測や展望\n\n信頼できる日本語の情報源を優先してください。"
}
```

#### 例2: 特定の業界に絞る

```json
{
  "role": "system",
  "content": "あなたはIT業界とテクノロジー分野に特化したリサーチャーです。技術的な詳細と業界動向に焦点を当て、日本語で回答してください。"
}
```

#### 例3: グローバルな視点

```json
{
  "role": "user",
  "content": "以下のトピックについてグローバルな視点で調査してください：'{{ $json['調査キーワード'] }}'。\n\n日本国内だけでなく、海外の最新動向や事例も含めてください。可能であれば、日本と海外の比較や違いについても言及してください。"
}
```

## プロンプト変更のベストプラクティス

### 1. 段階的に変更する

一度に多くの変更を加えると、どの変更が効果的だったか分からなくなります。1つずつ変更してテストしましょう。

### 2. 実行結果を保存する

変更前後の結果を比較できるように、n8nの実行履歴を活用しましょう。

### 3. A/Bテストを行う

同じキーワードで異なるプロンプトを試して、どちらが良い結果を生むか比較しましょう。

### 4. プロンプトをバージョン管理する

効果的だったプロンプトはテキストファイルで保存しておきましょう。

### 5. フィードバックループを作る

生成されたブログを読んで、改善点をプロンプトに反映させましょう。

## トラブルシューティング

### 生成される記事が短すぎる

**解決策**: 文字数指定を明確にする

```javascript
- 必ず2500文字以上で書いてください
- 各セクションは300〜500文字で詳しく説明してください
```

### 生成される記事が冗長

**解決策**: 簡潔さを強調する

```javascript
- 簡潔で要点を押さえた文章にしてください
- 不必要な繰り返しを避けてください
- 1文は40文字以内を目安にしてください
```

### 情報が古い

**解決策**: Perplexityプロンプトで最新情報を要求する

```json
{
  "content": "2025年1月以降の最新情報に焦点を当てて、以下のトピックについて調査してください：'{{ $json['調査キーワード'] }}'"
}
```

### 出典が不明確

**解決策**: 出典の明記を要求する

```javascript
- すべての統計データや引用には、必ず出典を明記してください
- 出典は「（出典：〇〇）」の形式で記載してください
```

## サンプルプロンプトセット

### セット1: ニュース記事風

- **ブログライター**: ジャーナリスト風、客観的、1500文字
- **タイトル**: 数字とキーワード重視、25文字以内
- **HTML**: シンプル構造、目次なし

### セット2: 詳細解説記事

- **ブログライター**: 専門家風、詳しい、3000文字
- **タイトル**: 「完全ガイド」「徹底解説」
- **HTML**: リッチコンテンツ、目次・FAQ付き

### セット3: カジュアルブログ

- **ブログライター**: フレンドリー、会話的、2000文字
- **タイトル**: キャッチーな表現、絵文字なし
- **HTML**: シンプル構造、読みやすさ重視
